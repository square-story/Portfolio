🧩 The Problem: Leetcode 2269 — Find the K-Beauty of a Number

I was tackling Leetcode 2269. Find the K-Beauty of a Number. The idea is simple: given a number and an integer k, find how many substrings of length k divide the original number (assuming substrings as numbers themselves). Easy, right?

I started converting the number to a string, slicing it to generate all possible substrings of length k, then checking if each one divides the original number.

Pretty straightforward... until it wasn't. 😅


The Bug: substr() vs substring()

Initially, I used this line to get the substring:

```jsx
const sub = numStr.substr(i, k);
```

But then, out of curiosity (and partly just testing), I switched it to:

```jsx
const sub = numStr.substring(i, i + k);
```

Boom. Different output.

Wait... what?

Both returned substrings of length k, but when I dug a little deeper — I realized these two methods aren’t as interchangeable as I assumed.

**🤯 The Subtle (but Crucial) Differences**

Let’s break it down:
String.substr(start, length)

    start: The index to start from.

    length: How many characters to extract.

    ✅ Returns a substring of given length starting from the start index.

    ❌ Deprecated — it's not recommended to use in modern JavaScript.

    ```jsx
    'hello'.substr(1, 3); // 'ell'
    ```

String.substring(start, end)
    start: Start index (inclusive).

    end: End index (exclusive).

    ✅ Returns characters between start and end.

    🔁 If start > end, it swaps the arguments.

    ✅ Safe and preferred in modern JavaScript.


    ```jsx
    'hello'.substring(1, 4); // 'ell'
    ```

Looks similar, right? But when you're dealing with edge cases or unclear variable values, the difference between length and end index becomes everything.


🧠 Lesson Learned

In the context of Leetcode 2269, both methods can work — but only if you're crystal clear on their arguments. I wasn’t, and that cost me some debug time I didn’t expect.

And honestly, that’s when I thought:

    “Wait — how many other devs are making this same mistake thinking these two are interchangeable?”
